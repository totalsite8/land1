Лендинг под вашу нишу через Arena Agent Mode: от нуля до публикации

Эта инструкция подходит для любой ниши: услуга, физический товар, интернет-магазин, SaaS, B2B, локальный бизнес, личный бренд, MVP или предзаказ. В ней — только действия: куда нажать, что ввести, что вставить в чат. Маршрут ведёт от «я ничего не знаю» до «у меня уникальный готовый лендинг на собственном домене, заявки из формы прилетают мне в Telegram». Обязательная трата по пути одна — домен ≈ 300 ₽ в год; всё остальное (GitHub, Arena, Vercel, Telegram-бот) бесплатно на старте.

Схема работы. Вы делаете около 10 ручных действий: аккаунты, домен, Telegram-бот, нажатие «Promote to Production» после каждой правки, финальный merge. Всё остальное — код, тексты, дизайн, сборка, GitHub и деплой — делает нейросеть в Agent Mode по файлу AGENT-PLAYBOOK.txt, который вы прикрепите к первому сообщению. Дальше она сама ведёт вас по шагам: что-то спрашивает, что-то показывает, ждёт вашего «утверждаю».

0. Самое главное правило Arena: «Продолжить работу», а не новый чат

Вся работа живёт в одной сессии (чате) Arena. Закрыли вкладку, вернулись на следующий день, зашли с другого устройства — на странице чатов найдите ваш проект и нажмите «Продолжить работу» (Continue). Никогда не начинайте новый чат для продолжения: в новом чате нейросеть ничего не помнит о проекте, а в старом — весь контекст на месте.

Где читать ответы нейросети. Всё, что делает и говорит агент, появляется в ленте чата — это обычная переписка, как в мессенджере. Длинные ответы прокручивайте до конца: последним блоком агент обязан писать «Ваш следующий шаг» — что конкретно сделать вам (ответить на вопросы, открыть превью, нажать кнопку в Vercel). Если видите карточки-вопросы с кнопками-вариантами — можно нажать подходящий вариант или просто написать свой ответ текстом в поле ввода.

1. Что понадобится (5–10 минут) + сразу соберите материалы

  1. Аккаунт Google — через него одинаково просто входят и в Arena, и в Vercel (подтверждение по телефону проходит, в том числе из России).
  2. Если какие-то сервисы недоступны в вашем регионе — включите подходящий законный VPN. Никогда не вводите пароли, коды 2FA и токены в чат с нейросетью.
  3. Файл AGENT-PLAYBOOK.txt — он идёт вместе с этой инструкцией. Открывается обычным Блокнотом: внутри можно дописать свои правила и пожелания — плейбук живой документ.

Как готовить свои файлы и куда их скидывать

  • Графика: логотип, фото продукта, команды, процесса, «до/после», скриншоты. Формат любой (jpg, png, heic), качество — чем лучше, тем лучше. Сжимать и переименовывать ничего не нужно: агент сам переведёт всё в лёгкий формат WebP и зашьёт в проект.
  • Тексты: описание услуги/товара, цены, адреса, реальные отзывы, ответы на частые вопросы — высылайте обычными сообщениями в чат или файлом.
  • Куда скидывать: прямо в чат Arena — кнопкой прикрепления (скрепка/плюс рядом с полем ввода). Присылайте изображения пачками и обязательно с подписями, что на каждом и где оно должно жить: «1 и 2 — логотип в шапку, 3 — фото для первого экрана, остальное — в блок про цех». Без подписей агенту приходится угадывать.
  • Присланные файлы не хранятся «в памяти чата»: агент раскладывает их в проект на GitHub, откуда Vercel автоматически отдаёт их на ваш сайт при каждой публикации. Поэтому файлы присылайте именно вложениями, а не ссылками «где-то в интернете».

2. GitHub: аккаунт и пустой репозиторий

GitHub — это облачная папка проекта. Нейросеть будет писать в неё код сама, вам нужно только создать её.

  1. Откройте github.com → Sign up → укажите ваш e-mail → придумайте пароль → имя пользователя → подтвердите код из письма.
  2. Рекомендовано: аватар (правый верхний угол) → Settings → Password and authentication → Enable two-factor authentication.
  3. Создайте репозиторий: кнопка + вверху справа → New repository → Repository name: например my-landing → выберите Private → поставьте галочку Add a README file → Create repository.

Готово, когда вы видите страницу репозитория с файлом README внутри.

3. Arena.ai: вход и подключение репозитория

  1. Откройте arena.ai — ссылка ведёт сразу на страницу чата-агента → войдите через Continue with Google.
  2. Создайте новый чат и убедитесь, что включён Agent Mode (режим, где агент сам работает с кодом и репозиторием).
  3. Подключите GitHub-репозиторий: в чате нажмите кнопку подключения репозитория → авторизуйте GitHub → выберите созданный репозиторий.

Важно: вся работа живёт в этой одной сессии. Возвращайтесь кнопкой «Продолжить работу» (шаг 0). Arena сама создаст рабочую ветку в вашем репозитории — в main агент ничего не пушит до финала.

4. Первое сообщение — главное действие. Нажмите «Отправить» — и работа началась

  1. В чате Arena нажмите кнопку прикрепления файла (скрепка/плюс рядом с полем ввода) и добавьте к сообщению файл AGENT-PLAYBOOK.txt.
  2. В поле сообщения вставьте текст из шаблона ниже, заменив нишу на свою.
  3. Нажмите кнопку отправки (стрелка в поле ввода) — до этого нажатия нейросеть ещё не начала работать, после — проект запущен.
Arena — чат проекта (Agent Mode)
📎 AGENT-PLAYBOOK.txt
Это плейбук проекта — следуй ему… Моя ниша: …➤ Отправить

Схема интерфейса (не точный скриншот): расположение кнопок может чуть отличаться.

[к сообщению прикреплён файл AGENT-PLAYBOOK.txt]

Это плейбук проекта — следуй ему на всём протяжении работы.
Моя ниша: [одним предложением — что вы продаёте или хотите проверить, для кого, в каком городе/масштабе. Пример: «Делаем мебель на заказ из массива, работаем по Казани, хотим заявки на расчёт»].
Начни по плейбуку с Фазы 0.

Это шаблон — скорректируйте формулировки под себя и добавьте свои детали. Это правило действует для всех промптов в инструкции: чем конкретнее ваш текст, тем точнее результат.

После отправки нейросеть сама: установит технический фундамент со всеми библиотеками, соберёт сайт-заготовку, закоммитит и запушит на GitHub, а затем начнёт интервью. Увидев сообщение «Фундамент готов» — переходите к шагу 5, пока она задаёт вопросы.

5. Vercel сразу: регистрация и импорт проекта (2 минуты, делается один раз)

Делаем это в самом начале сознательно: у чата Arena есть предел объёма, а Vercel даст вам постоянные ссылки-превью и канал публикации на домен с первых правок. Все клики — на стороне Vercel, агенту ничего настраивать не нужно.

5.1. Регистрация — через Google, не через GitHub

  1. Откройте vercel.com → Sign Up → Continue with Google → выберите ваш Google-аккаунт.
  2. Vercel попросит подтвердить номер телефона кодом из SMS — введите номер и код. Из России проходит.
  3. План (лимиты) не выбирайте и карту не привязывайте: бесплатного хватит для всей инструкции.

5.2. Импорт проекта с GitHub — по кликам

  1. На главной панели Vercel нажмите Add New… → Project.
  2. Раздел Import Git Repository. Если список пуст — нажмите Add GitHub Account / Continue with GitHub → в окне GitHub подтвердите установку приложения Vercel (Install) → выберите «Only select repositories» → ваш репозиторий → Save.
  3. Теперь репозиторий виден в списке — нажмите Import напротив него.
  4. Экран «Configure Project»: Framework Preset определится сам как Next.js — ничего не меняйте, просто нажмите Deploy.
  5. Ждите 1–3 минуты до статуса Ready — сайт уже живёт на техническом адресе вида имя-проекта.vercel.app.
Vercel — Dashboard → Add New… → Project
Import Git Repository: ваш-логин/my-landing Import
Configure Project → Framework Preset: Next.js (определён автоматически, ничего не трогайте)
Deploy

Схема интерфейса (не точный скриншот).

5.3. Как это работает дальше, без вашего участия

  • Каждый push агента → Vercel собирает новую Preview-версию (видно в Project → Deployments). Основной адрес при этом сам по себе не меняется.
  • Хотите, чтобы свежая версия появилась на вашем домене — один клик по шагу 9 («Promote to Production»). Сессия Arena от этого не закрывается.

6. Как разговаривать с агентом: читать, отвечать, спорить

  • Где читать: всё — в ленте чата Arena. Дочитывайте ответы до конца: последний блок «Ваш следующий шаг» — это то, что от вас ждут прямо сейчас.
  • Как отвечать на вопросы: если агент прислал вопросы с кнопками-вариантами — жмите подходящий вариант (или пишите свой вариант текстом); если вопросы текстом — отвечайте текстом, можно коротко и списком, можно не на все сразу. Нет ответа — напишите «не знаю, работай с гипотезой», агент пометит её и пойдёт дальше.
  • Если выводы агента вас не устраивают (бриф, позиционирование, варианты дизайна) — не молчите и не соглашайтесь «лишь бы было». Напишите прямо: «Ты неправильно понял. Я хочу, чтобы лендинг был про …, главное для меня …». Агент обязан зафиксировать вашу правку дословно и пересобрать выводы — это штатная часть процесса, а не конфликт.
  • Выбор вариантов: когда агент даёт варианты позиционирования или концепции — отвечайте коротким Утверждаю вариант N, чтобы он не угадывал.

7. Интервью: качество ответов = качество лендинга

Нейросеть проведёт глубинный опрос раундами. Правила хорошего ответа:

  • Конкретика вместо общих слов: не «качественно и быстро», а «заявка теряется, если клиент пишет ночью».
  • Дословные фразы ваших клиентов ценнее любых формулировок агентства.
  • Цифры и примеры из практики; где данных нет — честно пишите «не знаю», это нормально.
  • Нейросеть обязательно попросит 2–4 сайта-референса, которые вам нравятся (любой тематики — важно, что именно нравится), и позже — ваши изображения/логотип. Вы уже собрали их на шаге 1: присылайте пачками с подписями, агент сам переведёт в WebP и расставит по странице.
  • Не просите «сделай красиво» до стратегии: плейбук намеренно ставит исследование раньше дизайна — так лендинг получается про вашу нишу, а не шаблонным.

Если отвечать на часть вопросов сейчас нечем:

На эти вопросы пока нет данных — работай с гипотезами и помечай их [НУЖНО ПОДТВЕРДИТЬ]. Продолжай по плейбуку.

8. Темп: редкие промпты на весь проект

Обычно вводить ничего не нужно — плейбук ведёт сам. Но пригодятся:

  1. Если агент остановился и ждёт: 
    Продолжай по плейбуку: выполни следующую фазу, пришли результат и скажи, что нужно от меня.
  2. Если потерялись в процессе: 
    Статус: что уже сделано, какая сейчас фаза, что именно нужно от меня для следующего шага.
  3. Если написали «ты неправильно понял» — после его пересборки выводов выбирайте коротким Утверждаю вариант N.
  4. Если хотите ускорить этап: 
    Предложи не больше 3 вариантов и порекомендуй один с объяснением. Жду моего выбора.

9. Публикация каждого изменения на ваш домен — без потери сессии (Promote)

Ритм проекта такой: вы пишете правку → агент правит, собирает, пушит → Vercel за 1–3 минуты собирает новую версию → вы нажимаете Promote — и она на вашем домене. Сессия Arena при этом живёт дальше, merge не нужен. Плейбук обязывает агента самого заканчивать каждое изменение напоминанием об этом деплое.

  1. Откройте Vercel → ваш проект → Deployments.
  2. Найдите самый верхний деплой со статусом Ready из рабочей ветки агента (ветка называется примерно arena/…).
  3. Справа в строке деплоя — кнопка ⋯ → Promote to Production → подтвердить.
  4. Через полминуты ваш домен показывает свежую версию.
Vercel → Project → Deployments
● Ready arena/… Preview · 2 мин назад ⋯ → Promote to Production
ниже — старые деплои, их не трогаем

Схема интерфейса (не точный скриншот).

Один раз проверьте галочки переменных: Vercel → Settings → Environment Variables — у каждой переменной (адрес сайта, токен бота и т.п.) должны стоять галочки Production и Preview. Иначе версия, поднятая через Promote, окажется собранной без этих значений (форма/адреса не сработают).

10. Как смотреть результат: два окна, обе без потери сессии

  1. LIVE PREVIEW в Arena — кнопка/вкладка предпросмотра рядом с чатом. Это всегда самая свежая версия прямо из рабочей сессии. Проверяйте её после каждого этапа.
  2. Ваш домен (после шага 9) — та же версия, но уже публично: её можно показывать клиентам и открывать с телефона.
  3. Vercel Preview URL — публичная ссылка конкретной версии: Project → Deployments → верхний деплой со статусом Ready → клик по нему → ссылка вида имя-проекта-abc123.vercel.app. Удобно, чтобы сравнить «было/стало» или показать кому-то без публикации на домене.

Не переходите по «сырым» ссылкам песочницы вида https://3000-....e2b.app — они требуют служебный токен и не открываются напрямую. Работают только три способа выше.

Если LIVE PREVIEW сломался (белый экран, ошибки __webpack_modules__ или React Client Manifest) — это не дизайн, а закэшированная старая сборка. Скажите агенту:

Превью сломался: [вставьте текст ошибки]. Почини по правилам плейбука: останови сервер, удали кэш .next, собери production, перезапусти, проверь HTTP 200. Дизайн и код страниц не меняй.

11. Свой домен или поддомен

Любое доменное имя, купленное у любого регистратора, привязывается одинаково. Ниже — точные шаги на примере панели my.ru-tld.ru (у других регистраторов названия кнопок почти те же).

Вариант A — поддомен (проще, рекомендуем для старта, например landing.[ваш-домен].ru)

  1. Войдите в кабинет регистратора → откройте ваш домен → раздел DNS / Управление зоной. NS-серверы не трогайте.
  2. Добавьте запись: тип CNAME, имя (хост) — landing (или www, app — любое слово), значение — cname.vercel-dns.com → сохранить. Если A-запись с таким же именем уже есть — отредактируйте или удалите её: A и CNAME на одном имени конфликтуют.
  3. В Vercel: ваш проект → Settings → Domains → введите полный адрес landing.[ваш-домен].ru → Add.
  4. Дождитесь статуса Valid: Vercel сам проверит запись и бесплатно выпустит SSL (обычно минуты, из-за DNS иногда до суток). Не включайте проксирование/CDN-флажки у регистратора — сертификат выпускает Vercel.
  5. Проверка: адрес открывается по https:// без предупреждения о сертификате.

Вариант B — корневой домен [ваш-домен].ru

  1. В DNS вашего домена: A-запись с именем @ → значение 76.76.21.21; CNAME с именем www → cname.vercel-dns.com.
  2. Дальше — пункты 3–5 из варианта A, только вводите корневой адрес.

Финал настройки (один раз, после успешной привязки домена): Vercel → Settings → Environment Variables → добавьте NEXT_PUBLIC_SITE_URL = https://ваш-адрес (с https://, без слэша в конце; галочки Production и Preview) → Deployments → актуальный деплой рабочей ветки → ⋯ → Promote to Production. После этого проверьте ваш-адрес/robots.txt (должен быть Allow: / и строка Sitemap) и /sitemap.xml.

Vercel → Settings → Environment Variables
NEXT_PUBLIC_SITE_URL https://ваш-адрес
окружения: ☑ Production ☑ Preview Save

Схема интерфейса (не точный скриншот).

Подготовь проект к публикации на домене [ваш адрес]: попроси у меня только то, что делается руками. Проверь metadata, favicon, Open Graph, robots и sitemap — они должны брать адрес из NEXT_PUBLIC_SITE_URL и быть закрыты для индексации, пока переменная не задана. Дай точный чек-лист действий в Vercel и у регистратора.

12. Telegram-бот: заявки из формы прилетают вам в Telegram

Это бесплатный канал приёма заявок: без почты, без CRM, без backend-серверов. Делается один раз за 10 минут. Ручные действия — только ваши; нейросеть настраивает код сама.

12.1. Создайте бота

  1. Откройте Telegram → в поиске введите @BotFather (официальный, с синей галочкой) → Start.
  2. Отправьте команду /newbot.
  3. BotFather спросит имя бота — введите любое понятное, например Заявки с моего лендинга.
  4. Затем спросит username — обязан быть уникальным и заканчиваться на bot, например moysite_zayavki_bot.
  5. В ответ BotFather пришлёт токен вида 123456789:AAEhBOweik6ad.... Это секрет: никому не показывайте и не вставляйте в чат — он пойдёт только в Vercel (пункт 12.3).

12.2. Узнайте свой chat_id

  1. Откройте своего нового бота (ссылка в сообщении BotFather, вида t.me/moysite_zayavki_bot) → нажмите Start → отправьте ему любое сообщение, например «проверка».
  2. Откройте в браузере адрес https://api.telegram.org/botВАШ_ТОКЕН/getUpdates (подставьте токен целиком вместо ВАШ_ТОКЕН, слово bot перед ним оставьте).
  3. На странице найдите "chat":{"id": — число после него и есть chat_id (у личного чата это положительное число).

12.3. Включите доставку

  1. Скажите агенту промптом ниже — он скажет точные имена переменных и подготовит код.
  2. Vercel → ваш проект → Settings → Environment Variables → добавьте две переменные (имена подскажет агент, значения: токен из 12.1 и chat_id из 12.2). Галочки: Production и Preview.
  3. Чтобы переменные попали в живой сайт: Deployments → верхний деплой рабочей ветки → ⋯ → Promote to Production.
  4. Проверка: отправьте тестовую заявку с сайта → сообщение должно прийти в Telegram. До настройки форма честно показывает «приём настраивается» — это правильная защита, а не поломка.
Настрой приём заявок из формы в Telegram: серверный endpoint + отправка через Bot API. Без ключей в окружении форма обязана показывать честную ошибку и альтернативный способ связи, а не ложный успех. Скажи, какие именно переменные окружения мне добавить в Vercel (имена и куда вставить значения). Сами значения я внесу руками — в чат их не присылаю.

13. Цикл доработок: от превью до «меня всё устраивает»

У этого этапа нет финального пункта — вы крутите его, сколько нужно. Принцип одного витка: смотрите LIVE PREVIEW или ваш домен → говорите, что не нравится, обычными словами → нейросеть правит, собирает, пушит → по её напоминанию вы жмёте Promote to Production (шаг 9) → домен обновился, смотрите снова. Сессию не закрывайте.

Что можно просить — просто и по-человечески

  • Цвета: «сделай спокойнее», «замени акцентный цвет на синий», «тёмный hero, светлые секции».
  • Шрифты: «заголовки строже», «другой шрифт, без засечек», «крупнее подзаголовок».
  • Hero-блок: «метафора не заходит», «сделай проще», «добавь движение, но без 3D», «предложи 3 другие концепции».
  • Тексты: «перепиши заголовок увереннее», «короче», «без этого абзаца», «добавь ответ на возражение про цену».
  • Структура: «поменяй местами блоки», «убери секцию», «добавь блок про этапы работы».
  • Влияние на мышление агента: «ты неправильно понял, я хочу…» — пересоберёт выводы; «утверждаю вариант 2» — зафиксирует выбор.

Новые изображения на любом витке

Присылайте в чат пачками с подписями, что куда («это замени в первом экране», «это добавь в блок отзывов») — агент переведёт в WebP, вставит и запушит.

Выход из цикла — финальный merge

Когда версия на домене вас полностью устраивает и вы готовы закрепить проект — пишете: Готово к merge: создай Pull Request (или «готов смержить»). Агент создаст PR, вы нажмёте Merge pull request → Confirm merge на GitHub — рабочая ветка станет основной.

Помните: merge автоматически закрывает текущую сессию Arena — поэтому он делается один раз, в самом конце. Сам сайт на домене от merge не изменится (та же версия уже стоит через Promote) — merge нужен для порядка в репозитории. Дальше можно открыть новый чат, подключить тот же репозиторий и продолжать правки по той же схеме.

14. Аналитика и рост по данным

  1. Создайте счётчик аналитики (например, Яндекс.Метрика → Добавить счётчик → введите адрес сайта) и получите его номер.
  2. Сообщите в чат только номер — агент подключит всё через env-переменную (галочки Production + Preview), без счётчика в коде трекинга не будет вообще.
Подключи аналитику по номеру счётчика [номер] через публичную env-переменную: без переменной никакого трекинга нет. Настрой события: клик по главному CTA, дочит до формы, начало заполнения, успешная отправка, ошибка отправки. Скажи, какую переменную добавить в Vercel.

Затем добавьте сайт в Яндекс Вебмастер и Google Search Console (подтверждение домена → отправка sitemap) — так поисковые системы быстрее его найдут.

Улучшения — только по данным, раз в неделю:

Вот данные недели: [цифры из метрики, сообщения клиентов, где теряются]. Отдели факты от интерпретаций. Предложи максимум 3 гипотезы роста: проблема, сегмент, изменение, метрика успеха, риск. Ничего не реализуй до моего выбора.

15. Правила, которые защищают проект (краткий чек-лист)

  1. Никаких выдуманных фактов: отзывы, клиенты, цифры, цены, сроки, гарантии, интеграции и «дефицит» — только то, что вы подтвердили. Нет факта — честный статус («пилот», «ранний доступ», «проверяем спрос»).
  2. Один приоритетный сегмент и одно главное действие на страницу. «Для всех» не конвертит никого.
  3. Лендинг должен быть понятен без WebGL и тяжёлых эффектов: сначала смысл и типографика, потом анимация как улучшение. На телефоне — никакой горизонтальной прокрутки.
  4. Если на странице есть набор позиций (услуги, тарифы, товары) — каждой позиции свой якорный блок: узнаваемая ситуация, боль, честный статус, шаги работы, CTA; список работает оглавлением. Контент каталога живёт в одном источнике данных, а не в разметке.
  5. Форма: состояние загрузки, настоящий успех только после подтверждения сервера, понятная ошибка, минимум полей, без запроса паролей и чувствительных данных.
  6. Финальная проверка каждого этапа нейросетью: npm run lint и npm run build без ошибок, затем commit и push в рабочую ветку. Просмотр — через LIVE PREVIEW, домен (после Promote) или Vercel Preview URL.
  7. Домен обновляется через Promote to Production после каждой правки — сессия при этом живёт. Merge в main — один раз в конце, по вашей прямой команде, потому что он закрывает сессию.

16. Финишная точка: как понять, что проект завершён

Проект считается готовым, когда одновременно выполнены все пункты этого чек-листа. Пройдите его один раз в конце:

  1. Ваш домен (https://ваш-адрес) открывается без предупреждения о сертификате и показывает финальную версию лендинга, которую вы утвердили (merge в main сделан).
  2. Тестовая заявка с сайта приходит вам в Telegram через бота; при пустых полях форма показывает понятную ошибку.
  3. ваш-адрес/robots.txt показывает Allow: / и ссылку на sitemap; /sitemap.xml содержит ваш адрес.
  4. Ссылка на сайт в Telegram/WhatsApp разворачивается в красивую карточку (OG-изображение, заголовок, описание).
  5. Сайт удобно читается с телефона: нет горизонтальной прокрутки, кнопки нажимаются пальцем.
  6. Аналитика (шаг 14) подключена и считает посетителей и заявки.
  7. В чате вы видели финальный отчёт агента: lint и build без ошибок, коммиты запушены.

Всё сошлось — готово. У вас уникальный лендинг на собственном домене, заявки падают в Telegram, поисковики видят сайт. Дальнейшая жизнь проекта: правки и новые идеи — новый чат в Arena, снова тот же репозиторий и AGENT-PLAYBOOK.txt; улучшение конверсии — по данным аналитики (шаг 14).

17. Если что-то пошло не так

  1. Белый экран / ошибки модулей в Arena-превью → промпт из шага 10 (очистка кэша .next, production-сборка).
  2. Vercel пишет Build failed → откройте деплой → скопируйте текст ошибки → вставьте в чат: 
    Сборка на Vercel упала с этой ошибкой: [текст]. Найди причину, исправь, прогони npm run lint и npm run build локально, затем commit и push. Дизайн не меняй.
  3. Форма отвечает ошибкой «настраивается» / после Promote форма не работает → проверьте, что переменные добавлены (шаг 12) и у них стоят галочки Production и Preview; затем снова Promote свежего деплоя.
  4. Домен не становится Valid → проверьте, что запись CNAME, а не A; что под тем же именем нет второй записи; подождите до суток на обновление DNS.
  5. Вернулись в Arena, а чат пуст / не могу найти проект → найдите чат проекта в списке чатов и нажмите «Продолжить работу» (шаг 0). Не создавайте новый чат.
  6. Сессия Arena закрылась после merge → это нормально: откройте новый чат, подключите тот же репозиторий, прикрепите AGENT-PLAYBOOK.txt и напишите «Продолжи работу над проектом по плейбуку, покажи текущий статус репозитория».

Этот файл и AGENT-PLAYBOOK.txt — универсальны: в них нет никаких данных конкретных проектов. Агент дополняет инструкцию по ходу работы новыми универсальными правилами, не связывая их с вашей нишей. Схемы интерфейсов («shot»-блоки) — упрощённые рисунки «куда нажать», а не точные скриншоты: расположение элементов может немного отличаться. Если хотите настоящие скриншоты — пришлите свои агенту пачкой с подписями, он вставит их вместо схем.
